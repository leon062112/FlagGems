### Type of Change

Performance Optimization

### Description

Adds MetaX backend implementations of `sort` and `sort_stable`, adapted from the Hopper dispatch strategy in #8070 and extended with a MetaX-specific size-1 fast path.

- Dispatch on row length, row count, packed-key width and the input device's SM count.
- Use row sorting networks for short rows, packed-key tiled merge for larger rows, and a two-pass 16-bit radix path for selected long-row workloads. FP16/BF16/INT16 share the same dispatch criteria.
- Use single-warp initial runs for dense grids, stage-specific merge tiles and register limits, and skip merge-path partition searches when a program handles an entire pair of runs.
- Recover final values directly from packed keys where possible, preserving original signed-zero bits through a masked input load. Stable tie-breaking keeps original indices.
- Support strided and non-last sort dimensions with tiled copies, and use the existing `libentry`, Triton heuristics and JIT launch mechanisms.
- Return the input and an all-zero `int64` index tensor immediately for size-1 rows.
- Register `sort` and `sort_stable` through the MetaX backend operator module while keeping the public API unchanged.
